The six parts of a card
1
Data owner
Stream letter, role and GitHub login of whoever owns the data the screen reads. The design owner is always stream D. Board posts start with the agent label.
2
Reads
Artifact files under runs/<run_id>/ and the fields that feed the screen. Field-level detail is in docs/design/screen_fields.md.
3
Only in some states
Fields that exist only in some cases. Design the absent case too: absent means normal or not applicable, never an empty box.
4
States this screen must handle
Build every state listed, not only normal.
5
Pay attention
Rules specific to this screen, taken from the README. Read them before building.
6
Pending: not on main yet
A field the screen needs that no stage writes yet. Names may change. Draw it as pending, never as built.
The seven states
screen states, mapped to stage states in report.py state()
normal
The stage ran and values are present (stage state ok, cached or fixture).
not_run
No artifact. Show a dash and the reason, never 0 or a blank (a not_run is not a False).
refused
A model or a gate declined. Show it plainly as an outcome. Never as success, never worked around.
degraded
Ran with a fallback or a missing input: stand-in localisation, incomplete screening, sequence-only S7.
empty
Ran, and there is nothing to list (no survivors, no candidates).
loading
A stage or a fetch is in progress.
error
The stage failed, or needs a decision from a person (failed, needs user input).
How an agent uses a card
1
Find your screen and read its card, top to bottom.
2
Open the artifact paths in Reads. Take field names from the artifact, not from the picture.
3
Build every state in the card. Check the conditional fields in both their present and absent cases.
4
Apply the Pay attention rules. If a rule and the code disagree, post on the board and do not guess.
5
Never invent a value for a pending field. Show it pending and ask the owner.
6
Need a design change? Post on the board and mention @Abeeekoala. Only stream D edits this file.
Teammates implement from this file
Only stream D changes it. Before editing another stream's files, ask for a handoff on the board and wait for the owner or the team lead (AGENTS.md section 1).
Agent label
Every board post starts with [<human>'s <agent>], for example [Sam's Codex]. Mention people by GitHub login: @Abeeekoala, @kexinli0403-cell, @benjamin-codes-labs, @luk-e158, or @all.

How to read a value
FIXTURE
Taken from fixtures/nmb_fixture. Real data, but a 40-protein projection with stand-in localisation.
GENERATED
Produced by running the committed stage code (S8, S9, S10) on that fixture. A design, never a measurement.
README
Fixed text or a number quoted from the README, with its section.
DOC
Stated in a committed contract doc by the stage owner, not in a committed artifact.
PLACEHOLDER
A layout slot. The value is not computed. Never read it as a number.
NOT RUN
The stage did not run in this run. Shown as a dash, never as 0 or empty.
NOT ON MAIN
A field the screen needs that is not in the stage output on main yet.
STATE SPECIMEN
A state that did not occur in this run, drawn so the design covers it.
legend
States a stage can be in
ok
The stage wrote an artifact with status ok. Not a claim that the output is right.
not run
No artifact, or the stage says it had nothing to work on.
refused
A code model declined. Reported as an outcome, never engineered around.
incomplete
Ran, but a gate, tool or input was missing. Counts against the result.
blocked
A check failed. Nothing leaves the pipeline.
needs user input
The stage cannot choose for the person (an ambiguous name).
failed
A real defect: invalid protocol, failing session, unreadable artifact.
unverified
Code generated but not simulated. Not a pass.
fixture
The run is a fixture. Shown on the top bar and every screen.
src/vaxforge/report.py state()
Four rules every screen follows
A prediction is a hypothesis, not a measurement.
No predicted ELISA, flow or cytokine value appears anywhere in the product (README section 0).
A stage that did not run is shown as not run.
A dash with the reason, never a zero or an empty cell.
A refusal is shown as a refusal.
It is a distinct outcome of S9, with its own record. It is not a crash and not something to retry around.
Every number carries its source.
Stage, artifact and tool versions sit next to the value, so a reader can trace it.

Best of 12 predictors: 58.4% accuracy (AUC 0.60, MCC 0.17). Value is enrichment — top 10% of SoluProt rankings yielded 199 true positives vs 145 expected by chance, a 37.2% relative lift — not replacing the experiment
De novo binder design

Expression itself
ProteinGenerator designs intended to be soluble monomers passed 32/42; 8/19 when tryptophan-enriched. "It expresses" is itself a high-failure experimental outcome
Trial outcome prediction
HINT reports PR-AUC 0.772/0.607/0.623 (Ph 1/2/3) on its own benchmark; on an independent evaluation of 2,163 trials its balanced accuracy was 0.470–0.594 with overall MCC 0.050. Vaccine industry base rate
Phase 1 → approval 39.6% (industry-sponsored), 6.8% (non-industry). The narrowest transition is Phase 2 → 3 at 65.4% — exactly the point where immunogenicity data exists but efficacy data does not, which is the furthest any in-silico immune model can reach

How Figma was used

process evidence
A plain account of how this file was made and how it is used. Written on 2026-11-14. Each line is something that was done.
Generated from code
tool: generate_figma_design
1
The product design was written as one HTML page, docs/design/vaxforge_product_design.html, by Claude Code (an AI coding agent), from the README, AGENTS.md, the stage code and the committed fixture.
2
The page was imported with the Figma MCP tool generate_figma_design. A capture script runs in the browser on a locally served copy of the page and sends editable frames, text and shapes to this file. It is not a picture.
3
A test capture showed which HTML attribute sets a layer name. Tag names give Section, Container and Text. Only aria-label changes a name. So every frame, card and repeated part carries an aria-label, and the layers read 06 Wet-lab protocol, Owner and attention, Component / Status pill.
4
The page was imported three times. The first import kept the generic names. The second prefixed each name with its tag (Section - 06 ...) and was deleted. The third, from plain div elements, is the one in use.
Edited by hand in the editor
Figma web editor
1
Layer names were read in the Figma web editor, driven through browser automation, to check the result of each import.
2
The test frame and the second import were deleted there by hand.
3
The editor stopped opening for a while (the browser lost WebGL). After the browser was relaunched it reopened, and the first import was deleted, the page renamed to VaxForge, the capture’s root frame and Body ungrouped, 12 components made from the specimens and 25 variables added.
Still open
The 12 components (Status pill, Evidence badge, Button, Nav item and Callout are variant sets) sit in the Design system frame, and the 16 screens do not use them. The 25 variables in VaxForge tokens (15 of the 27 colours, 6 of the 9 spacing steps, 4 of the 7 radii) are not bound to any fill, so the screens still carry plain values. No Sections were made.
Why the design looks the way it does
design choices
Trust is the product
Every value carries an origin badge: FIXTURE, GENERATED, README, DOC, PLACEHOLDER, NOT RUN or NOT ON MAIN. A reader sees whether a number was computed or only specified.
Absence has its own look
Not run, refused, incomplete and blocked each have a pill. None uses the success colour.
Limits sit beside the numbers
Honest ceiling boxes (README section 4) are drawn next to the values they limit, not in a footnote.
Builders see what to watch
The Owner and attention card turns the README rules into per-screen instructions for each agent.
How the file feeds the agents
handoff
One card per screen
The Owner and attention card beside each screen is what an agent reads first: owner, artifact paths, conditional fields, states and rules.
Same names everywhere
Frame names match the screen codes used on the board (06, 07, 08) and in docs/design/screen_fields.md.
The source is text
The HTML in docs/design/ is the source. A change to the design is a change to a file that can be diffed.
One editor
Only stream D changes the file (AGENTS.md section 4). Teammates implement from it.
Not used
Figma Make was not used. The Plugin API tool (use_figma) was not used: the plan's monthly call cap on it was already spent. The TalkToFigma relay was not running.
docs/design/FIGMA_EVIDENCE.md holds the dated log
